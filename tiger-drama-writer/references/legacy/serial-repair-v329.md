# V3.29 serialized-scene anti-compression protocol

- Freeze the original five-episode batch before rewriting.
- Before generating each late episode, identify three playable scene engines, each with a goal, opponent's credible defense, changed tactical choice, and on-stage consequence. Do not let a state capsule replace these scene beats.
- For scene 3 (often the most compressed), write a genuine second contest instead of merely recounting scene 2. A demand from another character and a concrete sacrifice or binding decision both qualify.
- After the *raw* episode is written, audit it before advancing. If it is thin, mark the original as failed and revise in a separate file. Never count revised success as raw first-pass success.
- Run `scripts/check_serial_decay.py RAW.md REVISED.md`, alongside the structural, adversarial, and release screening; length increase by itself is not enough to prove quality.
- Track verified clean water, segregated unsafe water, consumed tools, injuries, power costs and evidence chain. A character's suspicion cannot be changed to fact by rewriting dialogue.
- Explicitly state limitations: output text is untimed; human causality and genre-payoff review remain necessary.


## V3.30 raw-batch regression

Screen both plain and Markdown-bold character labels. A single subthreshold episode must remain visible, even if other episodes pass. Verify the power/resource ledger and payoff independently. Length is not artistic quality or timed runtime.
