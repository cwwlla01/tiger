# V2.1 正式剧本完整度与爽点验收（强制）

## 1. 剧本与大纲分级
- OUTLINE: 事件、梗概、分集表，不计入剧本完成率。
- SCENE_DRAFT: 有场景、行动、对白，但存在空白、明显篇幅不足或不可演桥段。
- FULL_SCRIPT: 每集存在连贯的场景头、具体动作、完整可说对白、人物选择、状态变化、钩子；不以字数单独判定。
- TIMED: 完成真实朗读/排演计时才可标注实测时长；仅文字估计必须写“预估”。
- 交付时呈现计划集数、FULL_SCRIPT 集数、SCENE_DRAFT 集数、未创作集数，禁止‘写满60集’但交付60条梗概。

## 2. 每集展开前的四项门槛
- 事件的起因与结果明确，必须有在场角色主动做出改变局势的决策。
- 主角目标、阻力、战术和代价可被表演；反派有合理反制而非主动送资源。
- 为场景预留完整行为过程：发现→验证→选择→行动→后果；不能只写结论或口播。
- 每集至少一项具体状态变化（位置、资源、能力、关系、知识、势力、危险）。

## 3. 爽点账本
逐集记录：承诺的期待；铺垫；可见压力；主角决定；即时回报；反噬/新成本；下次更高目标。
- 不要将‘被羞辱’当爽点；胜利必须改变真实利益或关系。
- 在每个连续5集单元中至少安排一次明确的能力/策略兑现、一次人际/势力结果、一次强因果反转；剧情类型可调整比例，不能机械插入。
- 连续2集以上只有压制、逃亡、受挫而没有主动收获时报警，优先加入小胜利、关键认知回报或团队配合，不强塞逆天秒杀。
- 同样打法、同样反派失智、同样物件吸收连续重复要替换为新的成本或战术。

## 4. 长线属性与状态审计
- 每次增加属性点记账：物件来源、点数新增、分配、结余、基础值/有效值；角色不能双花点数。
- 战力提升改变战法不等于全能：展示针对性反制、环境边界与非战斗问题。
- 标记用户锁定事实/推导/自创；若变化可能推翻用户事实，保持用户事实并改写衔接。
- 每批交付附事实变化、关键伏笔、人物知情、伤势/位置、可直接续写的接续口。

## 5. 有限自动修复
每批执行完整度→硬逻辑→爽点账本→对白与动作审查。对最严重缺陷最多两次局部重写；保留前后证据。仍不通过时如实标为 SCENE_DRAFT 并说明问题。对60集任务优先输出可复用的全剧事件图与连续的完整剧本文件，不要将省略场景视为完成。
