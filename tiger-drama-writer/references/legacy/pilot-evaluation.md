# Pilot evaluation and repair loop

For a user asking for testing, pilot an original 3-5 consecutive episode sample under a concrete premise; do not evaluate only the outline. Deliver a transparent sample report separating observed text-level findings from viewer/retention hypotheses.

## Beat ledger (mandatory in autonomous drafting)
For each episode record: opening visual question, protagonist objective, active opposition, irreversible choice, 1-2 earned payoffs, ending turn, state delta, dramatic risk. Change payoff *type* across episodes (evidence, relationship, material advantage, moral cost, secret) rather than repeating public humiliation.

## First-pass rejection gates
- No concrete state delta or no protagonist action: restructure before writing.
- Coincidental proof or conveniently omniscient characters: plant evidence source, access and timing.
- Cliffhanger only an interrupted sentence: replace with action, new risk, or concrete visual reveal.
- More than two consecutive episodes dependent on the same insult/rebuttal mechanism: diversify the engine.
- Major plot critical text only on AI-generated prop/screen: plan composited overlay or confirm in spoken performance.
- Scene has unclear who physically owns or moves a key prop: fix blocking and continuity.

## Post-draft pilot report
List each episode's actual scene count, main hook, demonstrated payoff and end hook. Grade causal clarity, pace, character agency, dialogue, hook diversity, shootability (1-5, subjective). Cite a specific scene for every weakness. Patch at least one real weakness and re-grade; never label a paper review as audience validation or actual model-render testing.

## Scope honesty
A 5-episode pilot tests this instance's short-range consistency, not 60-episode retention or future model reliability. If scripts are partial, say so. Do not mark 'verified shootable' unless output actually underwent a generation/render test; mark 'screenplay oriented on paper' otherwise.
