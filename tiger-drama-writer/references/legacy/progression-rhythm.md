# V2.6 progression and payoff rhythm audit

Use when writing or revising 10+ episodes of power-progression stories that include management, survival or investigation.

1. Create a **promise ledger** from the premise: what concrete spectacle is the viewer promised? In an attribute-system drama, demonstrate actual earn -> assign -> test -> use -> new cost. Management victories cannot replace the promised progression for a whole ten-episode block.
2. Count upgrade events in each five-episode window. A ten-episode window with zero earned/spent/experimented points is a **major genre-promise failure**, unless the user intentionally imposes a no-upgrade arc. Never add free points to fix a failure.
3. Make every proposed upgrade have a traceable source, defined conversion, confirmed points, explicit spend and remaining balance. If past authoritative ledger is unavailable: mark prior balance UNKNOWN; stage a new *independently verified* collectible gain; label the result a scenario proposal rather than asserting the final stat total.
4. Pair each gain with a visually dramatized change in available choices: e.g. speed enables a rescue, force disarms an enemy, mental focus helps coordinate allies. A popup without a decision is not an earned payoff.
5. Alternate emotional engines across episodes: tactical inversion, resource win, trusted bond, painful price, reveal, pursuit, moral choice. Do not mechanically require a battle every episode; check that no block becomes only negotiations or ration meetings.
6. Define 2-3 crisis-to-payoff loops every ten episodes, each with a **setup EP -> attempted solution -> resistance -> paid EP** and a resulting irreversible world-state change. The main reward cannot always be 'information'.
7. For revision, preserve the original user canon and causal outcomes. Choose 2-4 episode slots and write concrete insertable scene beats (character, obstacle, action, obtained payoff, cost) instead of replacing the whole season or recapping what should improve.
8. Never confuse planning with finished scripts. Report episode-level progress as OUTLINE, SCENE_DRAFT, FULL_SCRIPT, or TIMED. Narrative scores are editorial judgement, not audience metrics.
