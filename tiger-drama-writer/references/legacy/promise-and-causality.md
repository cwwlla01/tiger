# 承诺忠实度与因果承接

## 区分用户要求与创作者选择的故事

确定集数之前，在同一份大纲中简洁、逐项绘制需求图：每项独立的明示事实、约束或要求的结果 → 在当前范围中的作用 → 计划用什么可观察的场景证据呈现，或有意延后。保留总结时可能遗漏的细节（例如，职业与就业状态是两项不同事实）。其作用可以是前景行动、因果背景、延后到整季的目标，或有意保持未解决。忠实记录用户要求；创作者自己的观众承诺不能取代它。不要另建一份档案，也不要为每个背景名词单独写场景。完成初稿后，将映射中的每项内容与实际剧本比较，而不只是检查大纲：标记为已呈现、有理由地变更或遗漏，并引用正文。回顾已完成作品时，先保存需求图，再与成片文本比较；不要为了迁就现有结局而改写原始承诺。

对于已经完成但没有原始故事弧大纲的剧集，根据源文事件重建一份简洁故事弧图，并标记为“源文推导”。用它检查因果推进和兑现分布；不要据此声称忠于原计划，也不要推测原作者意图。把分集摘要和制作备注视为需要与可演场景比较的主张。

区分以下三个边界：

- **用户要求的终点：**用户实际要求发生的事情。“开启钓鱼自媒体”意味着真正启动即可，不要求盈利。“靠账号翻身”则需要可信的、由账号带来的变化，不能只有发布作品或接到本地剪辑委托。
- **单集局部转折：**眼下发生的变化。试播集可以实现首次发布，同时把增长留待后续。应交付用户要求的一集，不要擅自编出整季。
- **创作者选择的类型奖励：**额外加入的愉悦体验。父亲的支持可以兑现亲情奖励，即使频道的外部观众仍为零；两者都要准确标示。

背景内容不必平均分配屏幕时间：已经完成的离婚可以影响一个选择，无须额外安排与前配偶对峙。不要为每个名词都编一场戏。但如果钓鱼是故事的核心卖点，就应在授权范围内呈现一次带来后果的钓鱼尝试。即使结尾确实开通了账号，如果全程用厨房里讨论空水桶的对白取代钓鱼，也没有兑现观众体验。

## 通过冲突呈现有边界的能力

使用简短的因果链：合理的既有习惯/资源 → 具体尝试的策略 → 限制/阻力 → 可观察的后果。程序员可以设计可复现的实验或定位故障；这类习惯并非程序员专属。应诚实说明这一区别。职业口头禅、剪掉六秒或重命名按钮本身都不能证明具有独特的职业能动性。

不要凭空编造技术奇迹，也不要把身边的专家写得无知。钓鱼专长可以属于父亲，账号运营可以交给搭档，主角负责结构化测试。让他们互不相容的限制使策略产生代价。如果专业准确性至关重要但尚不确定，应查证一手来源，或选择更简单且符合物理规律的动作。如果用户没有要求能力兑现，职业可以只作为因果背景。

## 让后续剧集承接前集决定

多集任务中，每个集间边界保留一条简洁的承接记录，不要另建大型档案：

`EPn concrete changed state → EPn+1 opening behavior → new resistance → changed tactic/cost`

审查时使用剧本原文。也要追踪故事内的媒体证据：观众/评论者只能对实际录制和发布的内容作出回应，不能回应大纲或未呈现事件。如果后续评论提到某个细节，就应在前集片段中先建立该细节，或调整回应，使其仅基于现有证据；不得暗中编造前集录像。如果 EP01 拒绝摆拍假鱼获，EP02 就不该原样重复同一诱惑再讲一遍道理。新压力可以导致人物退步，但要说明旧办法为何不再够用，并保留相应代价。对观看时长的新发现应改变下一次拍摄，而不只是成为一句教育性台词。

询问如果交换相邻两集的顺序，会破坏什么。如果没有相关变化，就检查它们是否重复了观众体验；可互换只是提示，不是禁止单元喜剧。也要检查行动能动性的分配：如果父亲每次都提供技能、创意、营救和最终判断，主角即使名义上是中心人物，也可能只是乘客。不要通过把父亲写成无能来修复这个问题。

## 不偷换标签，审查实际结果

使用简洁证据表：要求/承诺、准确原文及集数、观察到的结果、差距或限制。证据可以分布在整批剧集中。诚实标记已省略或仅被转述的行动。引文能证明文本位置，不能证明解释正确；不要因为表格填满就认证承诺已兑现。

将未履行义务与合理保持开放的未来目标分开说明。开通账号不等于事业翻身；若试播集只要求启动账号，没写事业翻身并非缺陷。修订应针对实际差距，并保留原稿。这些是编辑阅读指引，不是额外数值门禁，也不能证明观众会喜欢。

## 区分世界中发生的事件与录制证据

当录音、截图、消息或日志对剧情起重要作用时，应在正文中追踪以下三个层面：

| 层面 | 重要时剧本必须明确的内容 |
| --- | --- |
| 世界中发生的事件 | 谁在何处做了什么，使用了哪些物品或已知信息 |
| 录制到的内容 | 哪个设备正在录制、能拍到/录到什么、录制是否持续，以及谁能操作设备 |
| 后续使用 | 谁持有/剪辑源文件、播放或发布了哪一段，以及那段内容实际能够证明什么 |

场景可以写出某个动作，但剧中手机可能一直对着地面；这并不能提供清晰的动作教程片段。人物在场不等于该事件被录制下来。后续回放不能暗中补出缺失画面、没录到的话或时间戳。应在正文中建立必要的录制过程（适当时可在后文揭晓），修改后续片段声称/展示的内容，或如实保留证据缺口。人物可以撒谎或剪辑素材欺骗他人；要将其说法与叙事事实区分开，并让揭露出的原始素材/剪辑手法支持故事解决方案。不要为了交代每段录制的来源而提前破坏谜团。

对每段决定剧情的片段/录音，都要对照其源场景核验后续用途，不要只查紧邻的上一集。核对录制是否开启、设备朝向/收音范围、双手是否被占用、是否被打断、文件传输/剪辑过程，以及谁有权访问。不能仅凭片段存在就推断人物身份、录制日期、内容完整性或画外事件。这些是针对故事关键证据的选择性检查，不要求清点每一次无关紧要的手机使用。

必要时在现有承接/审查表中保留简短的来源→用途备注；不新增强制台账 Schema。唯一引文和匹配哈希能证明文本位置，不能证明设备确实拍到所声称的内容。对当前文件自审仍可能漏掉这一语义缺口。

将剧情所需的录制写成角色行动，例如稳住手机，或在打电话前停止录制。这属于剧本因果，不是制作镜头清单。不要为了补足它而增加镜头参数、摄影机设置、生成提示词或导演计划。修复时同时更新源事件/录制内容，以及依赖它的播放或结论；只在评估中补一句“有清晰录像”不算修复。
