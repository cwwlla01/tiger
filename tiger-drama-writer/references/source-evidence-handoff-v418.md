# V4.18 | 剧本事实与口白的可追溯交接（仅在跨阶段制作时启用）

当用户仅要求剧本/人物描述时，仍按 V4.17 交付完整可演剧本/描述；**不强迫用户看到元数据或中间审核表**。只有实际准备交给03导演、05视频编译时，才建立内部 `source_document`：真正保存的01文件相对或绝对路径、实际文件字节 SHA256、候选或已批准的可证状态。SHA只证明字节一致，不证明用户批准。

显式区分：用户当前原始要求、剧本中真实可演的 △ 动作及 `角色：台词` / `旁白：台词`、未在剧本出现的导演创作候选。每个关键不可丢事实（例如眼瞳转蓝、头发转蓝、不同人物身份、死亡顺序）在内部交接时列一个独立原文摘录，不把两条事实压成“已变身”。该证据必须是文件内的**精确原文**；无法落地文件则注明聊天来源未能由脚本核验，继续交付候选，不伪造哈希或批准状态。

`PUPPET_STRUCTURAL` 只表示可以强化人物气势、对峙和沉默节奏，**不授权新增诗号或旁白**。`PUPPET_MODERATE` 同样不保证旁白；若剧本确实包含说书人/诗号，必须将其写成可演台词并保留说话者。未写入01的台词不得在03/05仅凭布袋戏风格标签出现。用户明确要求古风诗号时，编剧先形成原创完整口白，录入真实01，再交下游；不能在提示词Skill擅自发明。

编剧阶段不承担镜头、模型参数和Seedance生成段的决策。审查实际字句而不是只读角色档案或风格标签。跨文件原文引用留在内部对照清单，不塞进演员对白和用户可复制的05提示词。
