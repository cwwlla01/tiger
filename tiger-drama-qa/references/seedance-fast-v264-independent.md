# V2.64 | 当前 Seedance 2 Fast 计划的独立 QA 流程

从用户当前实际要求的产物出发。只要求描述时不得擅自添加时长或视频计划；要求剧本不代表要求分镜；要求视频提示词时，应交付带有完整可用复制块的05。

对当前计划运行 `python scripts/audit_seedance_fast_v264_independent.py <manifest.json>`，并独立对照制作方产物；不得导入制作方的实现。检查确切渠道证据、用户时长要求的来源、剪辑入/出点、源文 SH 顺序、实际裁切结束前每个 SH 的可见结果、Take 之间的状态，以及每个 SH 合并边界所声称的理由。对于复杂互动，没有同一渠道的真实试拍不能证明合并可行；应退回分开生成，同时保持导演语义不变。

对于 `PUPPET_STRUCTURAL` / `PUPPET_MODERATE` 风格剧本，审查05是否添加了01中没有出现/未获批准的旁白、诗句、文字或舞台式特效。单有文字风格标签，不代表获准新增声音或视觉内容。自然语言审查必须实际阅读01、03、05；清单无法证明源文忠实度。

**严格限定旧版验证器的用途。** V2.59 和 V2.60 的15秒 Markdown 测试仅保留用于六个指定回归案例及明确要求的旧版格式兼容。不得仅因普通单镜头变身或动态时长场景缺少旧 SH 分钟格式就用它们拒绝。旧版4–15秒假设并不代表每种即梦 UI 选项；当前证据必须来自实际选择的渠道。

状态 `TEXT_STRUCTURE_PASS` / `FAIL` 仅用于结构化比较。真实素材、舞台真实感、观众效果、声音表现、照片及产品 UI 是否可用，都必须在实际观察前单独标记为 `NOT_VERIFIED`。
