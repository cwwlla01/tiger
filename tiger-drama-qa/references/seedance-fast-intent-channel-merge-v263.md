# V2.63 | 用户意图、确切渠道与有依据的分组（最高优先级）

## 制作前先路由输出

应用旧项目上下文前，先判断用户实际要求了什么：
- DESCRIPTION：撰写一段润色完善的视觉/表演描述，不生成视频 Take、不强加时长、带时码摄影计划、额外变体，也不要求用户在任意时长中选择。此前提到过 Seedance，不足以推翻用户当前明确提出的“描述一下”。
- DIRECTOR_STORYBOARD：只有用户要求镜头/分镜时才交付完整专业03。
- SEEDANCE_FAST_PROMPT：只有用户要求视频生成提示词或可执行的 Seedance 场景时才交付完成且可复制的05。导演/资产/QA 工作留在内部；展示用户实际要求的产物，而不是初步审查报告。
- 若用户明确要求“可用于 Seedance 的描述”，因为当前消息指定了媒介，应按 VIDEO 处理；否则遵循无歧义的产物要求。

## 时长是一个决策，不是模板

不得从六个历史测试案例继承15秒或五个编辑镜头。只有明确运行那六个指定案例，或用户要求15秒时，才应用对应案例约束。
- DESCRIPTION：不指定秒数。
- STORYBOARD/VIDEO：用户明确要求的时长优先。若未指定，应根据可观察节拍（情绪铺垫、触发、变化、稳定可见的结果）选择有戏剧依据的节奏，而不是从常见的“3/5/8/15秒”选单中挑选。短促变身通常保持为一个连续生成 Take，除非有艺术或物理理由需要剪切。
- 目标生成时长、剪辑后保留时长和成片时长是不同数值。仅在多镜头生成或用户明确要求节拍时码时，使用精确的内部 SH 时间线。自然的单镜头场景中，连贯动作序列可能比僵硬、强加的切点更有用。
- 根据已核实的确切渠道设置真实可选生成时长；若渠道 UI 的选项未知，应将元数据标为 CANDIDATE，并保留纯文本可复制块，不要声称选项已可直接提交。

## Seedance 2 Fast 确切渠道合同

不要混淆不同模型、API、产品系列或 UI 的事实。在提示词之外记录：
1. `platform`：根据用户实际选择的工具填写 JIMENG_WEB 或 VOLC_ARK_API；若未指定，仅在此前上下文明确且可信时沿用。不得暗中把即梦请求改成火山方舟 API。
2. 用户实际看到的准确 UI 模型名称；火山方舟 API ID `doubao-seedance-2-0-fast-260128` 仅适用于 VOLC_ARK_API，绝不可作为即梦控制字符串插入。
3. `proof_scope`：填写 USER_INTERFACE_VERIFIED、OFFICIAL_EXACT_CHANNEL、OFFICIAL_OTHER_CHANNEL、SERIES_ONLY 或 UNKNOWN。保留来源/日期和已确认的具体功能。Seedance 2.0 系列官方多镜头宣传不能证明即梦 Fast 的确切时长、逐镜头时码遵循情况或参考图绑定 UI。
4. 记录渠道专属的所选输入模式（文本、首帧、首尾帧、参考图、编辑等）及实际可用输入文件。除非该渠道已核实文件和语法，否则不得在可复制文本中加入 `@image1` 等参考标记或图片槽位。
5. 对于确切选择的 2.0 Fast，不得用 Seedance 2.0、2.5、2.5 flash 或其他 Fast 产品替代。

## 不要无理由合并生成片段

一次连续的摄影机/表演变化通常构成一个 Take。编辑 SH 切点和生成 Take **不可互换**。不得强迫每个 SH 对应一个 Take；也**绝不可**只为降低成本、满足多镜头功能、凑整时长或减少文件数量而把多个 SH 强行合并进一个 Take。

每次提议合并 SH-A 与 SH-B 时，都要写一份**内部**边界决策记录，包含：
- `dramatic_reason`：合并生成后观众具体能获得什么，不得只写“同一场景”或“节省调用”。
- `continuity_evidence`：固定的人物身份、准确空间/世界光源、动作结束/开始状态、参考资产，以及能够保持可读性的摄影机转场。
- `risk_mitigation`：失败模式、互动/肢体接触复杂度、选定确切渠道是否支持预期转场和参考素材，以及局部拆分的回退方案。
- `transition`：HARD_CUT、MATCH_CUT、OCCLUSION_CUT 或 CONTINUOUS_CAMERA；合并时写明各 SH 的确切局部时码范围。
- `channel_capability_basis`：确切渠道/模型证据；若未证明，应明确标为 CANDIDATE/PILOT_REQUIRED。

只有当合并能带来*具体的戏剧或连续性收益*，且摄影机空间关系、源文状态、输入/参考图映射和复杂度都相容时，才进行合并。共用地点、模型可能具备某项功能或降低生成成本，都不足以成为理由。如果收益有限，或高风险肢体互动尚未进行多镜头试拍，就保留独立 Take。只要能保护预期镜头和剧情兑现，拆分不算损失。

如果确切渠道未知，且没有使用禁止的参考标记，仍可提供可复制的 TEXT_CANDIDATE，但不得承诺确切的多镜头行为。后续进行的视频测试可以为某一特定分组提供证据；特定来源/场景的试拍证据绝不能推广到所有场景。

## 执行与核验

先运行 `scripts/audit_seedance_fast_v263.py --help`，再对内部 JSON 计划清单执行脚本。该清单绝不是面向用户的提示词内容。适用时，对多镜头05文件运行历史 V2.60 文本时间线检查。咨询独立 QA，并在脚本可用时运行 `tiger-drama-qa/scripts/audit_seedance_fast_v263_independent.py`；同时人工阅读实际源文及摄影机/光线状态。测试通过只证明清单结构正确，不证明质量、确切 UI 支持、像素一致性、表演质量或视频生成成功。

主要回归输入：“描述一个因恐惧而崩溃、突然瞳孔变蓝且头发变蓝的人。”如果用户只要求描述，这属于 DESCRIPTION。如果用户明确说“把它做成 Seedance 2 Fast 版本”，默认创作一个 SINGLE-Take 的连续情绪变身；只有确实需要作出制作时长决策时才指定场景专属时长。绝不可仅因为支持多镜头，就将其套成两镜头/五镜头测试案例。
