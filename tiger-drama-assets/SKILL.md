# 短剧资产总库与生产调度

## 定位与边界
- 担任**项目资产总库唯一记录与交接协调者**，不替代导演、不代替人物/怪物/场景图片的专业生产。
- 完整制作时，本 Skill 先基于冻结剧本快速提取本集资产、匹配全局造型，再把结果交给 `tiger-drama-director`；导演无需等待图像生产，但应使用已核实的身份和造型。03 后如有新的资产/造型需求，只处理增量，不重扫整集。
- 单独资产分析可从剧本直接开始；读取导演分镜用于核对实际镜头使用，而不是假定资产一定入画。只根据实际可访问资料判断复用，**不得声称读取了不可访问的历史资产**。
- 本 Skill 负责正式 Asset/Stage/Look ID、身份去重、造型沿用/新增、来源/版本/审核状态、缺口和任务交接；不替导演决定镜头、构图或造型如何揭示，不替代图片生产。
- 人物图片生产优先 `drama-character-asset-production`，若使用 Drama Studio 图位遵守 `drama-image-director` 的保存核验流程；怪物图片生产优先 `monster-stage-asset-director`。道具、场景图片如无专用 Skill，明确生产规格并交给实际可用的图片工具/制作流程；**不要假称已有独立道具/场景 Skill**。
- 无实际生成请求时只做资产记录、需求分析和交接，不生图、不产生虚假图位/图片路径。用户要求生图时，遵守对应生产 Skill 的身份审核和图位规则。

## 唯一模型
- 四类 `CHAR` 人物、`PROP` 道具、`SCENE` 场景、`MONSTER` 怪物。
- 结构：`category → individual_id → stage_id → look_id`。另设 `version`（图片或文字设定修订）及**镜头临时状态**（不进入三级树）。
- 个体是持续存在的同一身体、物件、空间或怪物实体；同名不必然同一物体，同身体不同人格不拆成两个人物资产。
- 阶段 = 可持续、可复用的核心状态（变身、进化、场景结构持久改变、道具功能形态改变）。造型 = 阶段下的服装、配饰、布置等可复用外观组合。瞬间动作、表情、暂时光照、污迹和手中位置通常是镜头状态。
- 示例：林渊/阿禾为同一个 `CHAR-001`；`S01` 林渊常态、`S02` 阿禾接管；同一服装应在新阶段明确继承，不凭空换装。`persona` 与 `body_id` 分开记录。
- 统一库负责分配正式编号；导演提出 `TMP-CHAR-01` 等临时编号时先核对别名和历史，再分配或映射正式编号。正式编号不得因名称变化而重置。
- 全局人类可读记录按 `全局资产/{人物|道具|场景|怪物}/{资产名称}-设定.md` 与 `{资产名称}-造型.md` 存储；Asset ID 写入设定文件，Stage/Look ID 与适用故事时间写入造型文件。重名冲突时在文件名加稳定ID后缀。已有 `asset-registry.json` 可作索引/兼容输入；不得同时维护两套冲突的权威资料。

## 每次执行的流程
1. **锁定范围与来源**：确定本集定稿剧本、集数、可读的全局资产目录；无库时标记 `HISTORY_NOT_VERIFIED`。只处理用户指定集数及明确相关的前置状态。
2. **一次提取本集资产**：按剧本场次顺序抽取不同的角色、怪物、场景、道具、别名、首次出现及明确外观/状态变化；不逐镜重复提取，不扫描未指定的整季。
3. **定向匹配全局文件**：只查命中资产的设定/造型文件，核实 ID 与身份。用别名证据合并；重名不同实体不合并；证据不足标 `UNVERIFIED`。
4. **解析造型时间线**：剧本明确指定且库有造型时引用对应 Look ID；明确要求的新造型若不存在，则追加候选 Look ID 并保留来源；未指定新造型时沿用本集故事时间之前最近有效的已批准造型（按 `story_order/effective_from`，不按文件修改时间）。首次资产初始化设定文件与首个 Look 记录；缺少的视觉信息保持未知。
5. **区分稳定与瞬态**：持续、可复用的身份/形态变化建 Stage；可复用服饰/外观组合建 Look；伤势、污迹、湿润、表情、手持物等临时状态写入本集/镜头状态，不滥建 Look。
6. **建立本集节拍映射**：为每个资产记录本集相关场次/节拍、选用的 Asset/Stage/Look ID、画内/画外/声音用途与状态转变。导演据此安排何时完整显露、遮挡或揭示；资产映射不决定镜头。
7. **标来源与批准状态**：设定来源取 `SCRIPT_EXPLICIT`、`APPROVED_HISTORY`、`ASSET_PROPOSAL` 或 `UNVERIFIED`；批准状态与是否有真实图片分开记录。`APPROVED` 仅由可追溯批准产生；助手 QC 不等于用户批准。
8. **写入并交接**：单集 `02-资产解析.md` 与同集 `剧本.md` 同级，不建 `解析/` 子文件夹。全局 Markdown 只追加新资产/新造型，不覆盖旧版本；JSON 如使用仅作索引/交接。无实际图像请求不生图、不虚构素材。
9. **03 后增量修订**：只在导演方案出现清单漏项、新的可复用造型或影响镜头的实质冲突时，补更新对应全局记录和本集02映射；不重跑其它资产，不替导演改镜头。

## 多集批次落盘

- 用户要求“剧本先定稿、再解析资产”时，等待指定范围的01通过文本审核并冻结后再做02；不得用资产拆解反过来替代或提前锁定未定稿剧情。
- 跨集复用的正式ID、人物阶段、造型与资产设定只维护在项目级全局资产目录，各集目录之外；单集只维护本集用到的资产映射与临时状态。
- 单集资产解析文件与源剧本同目录，不另建解析子目录。全局目录使用 `{分类}/{名称}-设定.md` 与 `{名称}-造型.md`；造型记录含 ID、来源/批准状态及故事时间适用范围。
- 如果用户只要导演分镜，03可只读查本集命中的造型，不强迫生成完整02；需要全流程时02先提供造型匹配，03后只接受增量补充。
- 未核实的历史库、参考图或审批继续标记未验证，不因目录结构而升级状态。
- 跨阶段、多集总控时读取 `$tiger-drama-orchestrator` 的 `references/creator-first-batch-workflow.md`；遵守用户指定批次与停止点，不自动顺延下一集。

## 接口合同
- 仅当生成或核验结构化 JSON 交接时读取 [references/contract.md](references/contract.md)；单集 Markdown 造型匹配不要求加载完整 JSON 合同。
- 需要文件校验时使用 `scripts/validate_registry.py`，它只验证静态结构与基本引用，不证明图像像素正确或用户批准。
- 参考空白模板 `assets/registry-template.json` 和 `assets/handoff-template.json`；模板数据不是实际项目事实。
- 若存储系统无法访问，使用本地可交付 JSON 和明确的 `REGISTRY_UNAVAILABLE` 标志；不要承诺跨聊天自动记忆或自动同步。

## 关键回归检查
- EP001 没写林渊长相，EP002 有历史已批准母版：沿用，禁止重造脸。
- 林渊→阿禾：同一身体不同阶段，头发/眼睛按剧本变，服装未变则继承。
- 两只巨鳄若为两个独立个体，不因同物种同造型而合并个体；可以共享物种设计模板但保留个体追踪。
- 场景门框持久损坏跨集保持；暂时的角色表情不创建新阶段。
- 导演首尾帧必须引用同一组明确版本，允许在一个 take 中记录 `S01→S02` 变化；不以帧数量推导资产数量。
- 未找到历史库、未读到真实图片、仅有文字描述时，分别如实标记；不虚构批准、生成或导入。
