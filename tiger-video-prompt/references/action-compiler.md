# 可执行视频动作提示词编译门禁

## 分类路由
- `PERFORMANCE`：单人物微表情、视线、呼吸、情绪；锁脸、服装、景别与视线目标。
- `TRANSFORMATION`：同体渐变，分变化过程和变化后表演；身份不变，不新增第二个身体。
- `CONTACT`：刀刃、撞击、跌倒、扶接；逐段写接触双方、接触点、方向、接触前后状态。高风险使用遮挡与结果镜。
- `MECHANISM`：机关动作必须写因果链，至少分受力→解锁→运动→结果；不同物件不能互换。
- `MULTI_ACTOR`：优先单镜头单主动作；多方互动用主客体、站位、进出画明确表达。
- `DEATH`：受击、反应、死亡结果可拆段；不能先死亡后继续活动。
- `POST_ONLY`：字幕、等级UI、倒计时、黑场音轨、不可见主观声音由后期处理。

## 每个执行子段必须包含
1. 明确的角色/怪物个体与空间（必要时关联母Take的资产ID）。
2. 摄影机所在侧、景别与单一可执行运动；不把剪辑指令伪装成一次生成。
3. 起始状态：人/物位置、伤口、服装、道具持有者、门/机关状态。
4. 主要动作：谁→作用对象→接触点/方向→动作先后。
5. 结束状态：可肉眼验证的状态变化及下一段继承约束。
6. 可后期元素及模型能力未验证项的诚实标记。

## 拆段规则
- 一段中有两个独立强接触、需要硬切换机位、连续复杂机械因果、变身+对白+摔倒+接人时必须拆段。
- 子段编号 `T-023A/B/C` 归属母镜头 `T-023`；不改变源事件，按顺序生成，后期拼接。
- 不允许只写“拆为两段”而不提供每段完整投喂提示词。
- 优先使用固定侧面机位、遮挡、反应镜头和结果镜降低AI生成风险；不删剧情必需结果。
- 任何已核实首尾帧与人物参考图须显式记录；没有图片则 `IMAGE_MISSING`，不得标为已准备。

## 静态审核
对所有母Take核对提示词覆盖；对每个高风险母Take核对可投喂子段、动作起止与跨段物理状态；对后期元素检查不得要求视频模型生成精确文字；对时长检查生成与编辑分别计算。静态通过不等于实际模型出片通过。
