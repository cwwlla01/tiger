# V2.64 | 当前 Seedance 2 Fast 路由优先于旧版案例检查

## 范围优先顺序
1. 用户要求描述 → 提供文字描述，不附带视频生成计划或时长。
2. 用户要求完整剧本 → 交付编剧产物（01）；要求分镜 → 交付完整03；要求 Seedance 提示词 → 交付完整可复制的05。
3. 对05，选择当前准确渠道 `jimeng_web` 或 `volc_ark_api`；不得把 API 选项、ID 或时长范围套用到即梦 UI。如果尚未观察到可选项，应交付 `CANDIDATE` 并如实简述限制，而不是声称内容可直接提交。
4. 根据源文/动作确定戏剧时长；用户指定时间优先。**不得默认15秒。** 一个视觉动作变化通常自然对应一个 Take；SH 并不机械地等同于 T。
5. 只有每个边界都有明确的叙事/摄影收益，且世界空间光线、人物/道具状态、确切渠道输入和风险都相容时，才合并 SH。模型泛化的多镜头支持、共用地点或节省调用都不足以构成理由。未经试拍验证的复杂接触动作应保持分开。明确给出局部拆分回退方案。

## 当前动态审查流程

使用 `python scripts/audit_seedance_fast_v264.py plan.json`。独立对应版本归 `tiger-drama-qa` 所有。计划仅供内部使用；用户的可复制块只能包含其要求的可执行视觉/表演/摄影机/声音指令，不得出现审计字段名或虚构的参考资料。每个生成 Take 都要记录可见兑现发生在**实际剪辑保留区间**内的时点；多镜头时，每个 SH 都要有自己的局部时间线和兑现点。保留片段时长与真正独立的 POST_ONLY 时长之和，必须等于导演选定的最终时长。保持源03中的剪辑/音频连续性及人物身份/灯光约定。

**历史范围隔离：** `scripts/audit_seedance2fast_v259.py`、`audit_seedance2fast_v260.py` 及匹配的 QA 脚本仍用于其原有目的：六个15秒回归案例/用户明确要求的旧版 V2.59–V2.60 Markdown 格式。绝不可把它们作为无关用户场景的通用门禁；这些脚本可能假设旧标点、精确时间范围和模型限制。若新版 `05` 使用不同布局，应核验其当前内部计划和实际可复制文本，而不是硬套历史案例格式。

## 布袋戏风格的对白/媒体保护

沿用用户批准剧本中的准确 `角色：台词`，以及明确写出的 `旁白：` 台词。不得仅因编剧标记为 `PUPPET_STRUCTURAL` 或 `PUPPET_MODERATE`，就擅自生成新的诗性独白、吟唱、旁白、传统风格字幕、环绕运镜、音乐或夸张变身特效。将表演和停顿写成可见动作；只有确实计划采用配乐/精确书法字幕时，才在相关处标为后期制作。世界内固定光源和主体运动比装饰性技法标签更重要。

## 证据限制

通过 `audit_seedance_fast_v264.py` 或其 QA 对应脚本，只能证明所提交的计划/提示词结构符合要求。只有在检查单独记录的生成结果后，才有真实模型视频或像素级证据。渠道证据和图像上传状态必须真实且具体。
