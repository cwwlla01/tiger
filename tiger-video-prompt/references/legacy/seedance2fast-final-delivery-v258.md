# V2.58 | Seedance 2 Fast 最终提示词交付与失败门禁

## 目标与优先级
- 用户明确选择 Seedance 2 Fast 并要求成片提示词时，**主交付只展示 `05-Seedance2Fast-视频生成提示词.md`**：按Take排列、每段一个可复制中文纯文本代码块，块外只放简短模型/生成时长/剪辑保留/编辑镜头/输入素材状态。不让用户逐轮催改，也不拿03/04/QA清单代替05。
- 03、04、素材索引及QA是内部生产与证据依赖。不得跳过导演质量；若源剧本只有一句话，可内部完成候选03，再编译 `CANDIDATE` 05，不能伪装为已批准权威母版。
- 核心四条必须同时做到：**多镜头合并决策、逐秒完整生成时间轴、电影摄影+灯光氛围+表演因果实编、独立质量门禁**。

## 已证实型号事实与不确定性（2026-11-16核对）
- 字节跳动官方 Seedance 2.0 系列发布文档确认 **15秒多镜头音视频输出**：https://seed.bytedance.com/zh/blog/official-launch-of-seedance-2-0 。这是系列级说明，不能作为Fast子型号逐帧遵守精确分秒的保证。
- 火山方舟官方模型清单列 `doubao-seedance-2-0-fast-260128`，支持文生、首帧、首尾帧、参考、编辑、延长；官方规格为 **4–15秒、24fps、480p/720p**：https://docs.volcengine.com/docs/ark/model-list?lang=zh ，https://docs.volcengine.com/docs/ark/video-generation-tutorial?lang=en 。此为火山方舟API能力资料，不代表用户即梦界面所有时长、分辨率、素材上传组合均一致；用户界面可选值需实测核对。
- 提示词里的 00:00.0–00:03.5 是**导演意图与剪辑定位**，不保证模型能精确按0.5秒切镜。缺用户当前入口证据时，标记 `UI_CAPABILITY_UNVERIFIED`，仍可交付**文本已核验**的可复制纯文本，不许宣称已成功提交或视频已通过。

## 两层镜头与合并策略
1. 从冻结03或明确的候选导演设计提取编辑镜头，先试探**同场景、同审美、同身份和连续叙事因果**的2–4镜合并。可多镜头并不代表所有镜头均需合并；复杂物理接触、硬切轴线模糊、提前暴露惊吓点、必须锁定不同参考输入时采用最小必要拆段。
2. 一次生成可包含多个编辑镜头。对每个Take明确 `生成时长`、`剪辑保留`、`镜头清单`、`是否合并及原因`，尤其**每镜头的开始-结束时间必须覆盖完整生成时长**；若剪辑只留前6.5秒、生成8秒，最后一个镜头必须写到8秒，说明余量是同镜头延续，不得只写6.5秒又标生成8秒。
3. 每镜头包括：动作可见起点→过程→终态；摄影机位置/主运动与戏剧动机、景别构图、轴线与焦点；世界光源受光和氛围（画面级全局继承 + 本镜局部变化）；声音/说话人；切点与切法（首镜无切换，其后`硬切/匹配切/遮挡转场`）；镜头数=时间段数；不可写「按剧情依次演绎」等抽象句。
4. 将通用美术与跨镜头不变量置于**单个复制块前部**，每镜具体节拍置于 `【00:00.0-00:03.5｜镜头1】` 等时间段内，末尾 `【终态】` 与 `【禁改】`，保证任一复制块独立可读。身份、灯光、道具、场景状态跨段连续。镜头语言优先于笼统形容词堆积。
5. 采用未验证上传的参考图不得出现 `@图片1`；只有文件确实可访问、已上传且确认入口语法时才写入。无图可选择符合实际能力的 `TEXT_TO_VIDEO`，不能强制任何镜头都制作首帧。
6. 生成过程可按导演风格选择固定、推、横移、弧形、手持等技法，但**每镜一个主摄影运动**；复杂运镜必须给轨迹、高度、朝向及终点。不要将电影运镜库机械堆叠到每个镜头。

## 交付前执行顺序（必跑）
1. 先编译05草案与内部03/编辑镜头清单。将 `模型、生成时长、剪辑保留、编辑镜头、合并决策、输入模式、素材状态` 写在Take块外；拷贝块内**只留Seedance需要的内容**。
2. 运行 `python scripts/audit_seedance2fast_delivery.py 05-Seedance2Fast-视频生成提示词.md --expected-shots SH01,SH02,...`。任何 `ERROR` 不得交付，必须修正文稿后重跑；脚本只对结构、时间和字段存在性负责。
3. **人工电影级审查**：检查镜头是否必要，揭示顺序是否正确，转场有无视觉证据、空间/光线/受光是否连续，心理变化能否可见，声音与动作时机是否正确，镜头合并是否过度，复杂动作是否应拆；发现缺陷自动修改并重检，不把建议丢给用户。
4. 若独立QA能力可用，交给 `tiger-drama-qa` 再审05的来源覆盖/角色/道具/时长/镜头起止/风险与缺素材。未实际调用独立QA不得自称独立验收。06拒收后内部回到03或05修复，返回通过的完整05，而不是仅给错误列表。
5. 标记证据等级：`TEXT_QA_PASSED`（结构+人工文本、按实记录）/`ASSET_UNVERIFIED`/`UI_CAPABILITY_UNVERIFIED`/`VIDEO_NOT_TESTED`；不得使用 `VIDEO_QA_PASSED` 除非检查真实生成视频。

## 门禁与诚实边界
- 静态脚本能确认时间区间、元素是否出现，**不能**确认影视审美质量、模型真正支持的即梦UI时长、生成效果、演员面容一致或画面物理一致。人工导演/QA必审。
- 一次生成多个镜头是**默认应考虑的方案**，不是强制所有Take至少两镜；单镜必须在块外明确保留的剧情/物理原因。`生成时长` 与 `剪辑保留`不可互换。
