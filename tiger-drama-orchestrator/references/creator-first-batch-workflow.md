# 创作者优先的分集批次流程

跨多个创作阶段或多集工作的任务按本参考执行；用户只要单集文字、单项审查或明确跳过阶段时，不强加整套流程。

## 先锁范围，再派工

- 记录用户指定的剧集范围、交付物、顺序和停止点。只读取这些剧集及其直接依赖；不因“全流程”默认扫描全季或重做已验收批次。
- 用户改变顺序、纠正故事结构或收窄范围时，立即以最新指令重排任务。旧大纲、旧报告和此前助手的解释都不能覆盖该澄清。
- 不确定“叙事顺序”“实际事件顺序”“角色所知/记忆”是否相同，先对照现行设定；不可把视觉呈现自动改成口述，也不可让角色记得其未亲历的共身经历。

## 01 剧本先冻结

- 用户要求“先定稿剧本，再做资产/分镜/提示词”时，先完成指定范围的01修订和文本审查；01未通过前不得创建新的02–06产物或生图任务。
- 按场景检查实际可演事件、动作因果、人物知识、集间状态与正典来源。用户明确要求某事件“演出来/有画面”时，不得用旁白或角色转述代替该事件。
- 剧本专用结构化检查器不识别项目标题格式时，记录一次格式限制并转人工来源核对；不要为迎合解析器重排剧本或反复运行无效工具。
- 用户已明确授权“审核通过即替换原稿”时：01候选必须先按来源逐项审查并通过；通过后将同一确切版本写回指定原稿，保存修订差异或可恢复快照并复核哈希。失败则不替换。不得再向用户重复询问已明确授权的同一动作。
- 01文本通过只表示剧本门禁通过，不代表资产图像、参考图绑定、视频或整包投产通过。

## 02–06 按集生产

- 指定批次的01冻结后，再按用户要求进入下游；单集只提取该集资产，不默认扫描全季。
- 按 `01 → 02造型匹配 → 03导演 → 04/05编译 → 按需06` 执行。02先从剧本提取本集涉及资产，再只查命中的全局资产设定/造型；03直接使用本集造型映射作导演输入。03产生新的可复用造型需求时，仅对02做一次定向增量，不全量重跑02或03。
- 单集产物与该集 `剧本.md` 同级存放（例如 `EP004/02-资产解析.md`、`EP004/03-专业导演分镜.md`），不要再建立 `解析/` 子文件夹。全季复用的人物、场景、道具ID和批准状态维护在各集目录之外的项目级全局资产库；单集文件引用全局ID，不复制全季总库。
- 若同名资产在库中缺失且本集有明确来源描述，初始化对应设定/造型记录及候选ID；未知视觉细节保留未知，不凭空设计。批准状态与ID分配分开管理。
- 造型“沿用上次”按故事时间线和有效状态判断，不按文件修改时间。检查后续集约束仅限用户指定的批次或直接涉及的连续性依赖，不扩展为全季扫描。
- 只有用户要求媒体生成且本轮明确批准时才进入实际生产；文本提示词不得伪装成生成或验收结果。
- 一个批次只执行一次对应的交接和QA闭环；源文件哈希没有改变时，不因下一阶段开始而重跑上游。资产发生增量时只重验引用该资产的镜头与下游产物。按用户指定的停止点结束，不自动扩到下一集。

## 交付

一次说明：哪些源文件已定稿/替换、哪些单集产物已完成、哪些门禁通过、媒体层仍未验证的事项，以及严格的停止位置。不要让用户逐轮追问“审核过没有”。
