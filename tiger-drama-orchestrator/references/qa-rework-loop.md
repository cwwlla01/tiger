# 06返工闭环

1. 06提出唯一工单：ID、严重度、来源文件与位置、源SHA256、证据、影响范围、责任专业Skill。
2. 总控路由至原生产Skill判断 `REPAIR_REQUIRED` / `FALSE_POSITIVE_CANDIDATE` / `NEEDS_AUTHORITY_DECISION`。不以06意见自动改母版。
3. 原生产Skill若认为需修复，生成候选文件和差异，列出受影响的下游文件与Take；若认为误报，提供可复核的来源证据。
4. 用户或明确授权的负责人决定是否升级权威版本。未经批准不得覆盖03或其他已冻结母版。
5. 下游依赖变更后重新编译受影响04/05并做映射检查；旧06结论失效。
6. 06独立复验。只有有证据的通过才可关闭工单；否则 `NOT_VERIFIED` / `BLOCKED`。
7. 最终只交付一份当前有效的06报告，保留历史工单记录但不重复追加相互矛盾的总结。
